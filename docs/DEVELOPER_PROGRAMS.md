# Developer program research

Researched against provider documentation on November 6, 2026. Accounts, permissions, regional availability, and provider rules can change. None of these programs is needed for the local demonstration.

| Program | Test environment and access | QuarantinePay boundary |
| --- | --- | --- |
| [Shopify development stores](https://shopify.dev/docs/apps/build/stores/development-stores) | A Shopify Partner account or merchant store with developer permissions and permission to create stores is required. A development store is for testing and can use Shopify's test gateway or a provider's test mode. It cannot process real transactions. | The optional read-only connector requires a user-controlled partner development store, Admin token, and read_products/read_orders scopes. It checks the development-store plan and returns at most ten products and ten test orders. It has not been externally tested here. A Shopify test order is separate from QuarantinePay settlement. |
| [eBay developer sandbox](https://developer.ebay.com/api-docs/buy/buy-requirements.html) | An eBay developer account can use many Buy APIs in the sandbox. Guest and member checkout methods require approval, including for sandbox access; production access is limited and approval is not guaranteed. | No eBay adapter is provided; the local demonstration does not depend on checkout approval. |
| [Square Sandbox](https://developer.squareup.com/docs/devtools/sandbox/overview) | A developer account and registered application provide a sandbox, test account, and sandbox credentials. Test values simulate payment processing without charging cards. | No Square adapter or externally confirmed Square transaction is included. |
| [PayPal Sandbox](https://developer.paypal.com/sandbox-testing/accounts) | Sandbox buyer and business accounts support testing without moving real money. QuarantinePay's optional PayPal integration requires separately configured Sandbox credentials. | A PayPal Sandbox result is externally confirmed only when PayPal actually returns and the application records that result. Replay results are local simulation. |

[PayPal's card testing documentation](https://developer.paypal.com/sandbox-testing/card-testing) lists test values and rejection triggers for supported Expanded Checkout integrations. Those triggers are provider- and integration-specific; QuarantinePay does not implement Expanded Checkout card fields. Never enter real card details into QuarantinePay. Use a provider-hosted Sandbox checkout only when it supports the intended test, and follow that provider's test instructions there.
